用語解説

3つの用語は、AIを使った開発の異なる領域を表しています。「Harness Framework」は本教材で再利用可能なプロジェクト構成に付けた名称です。

Prompt Engineering​

作業依頼を明確に伝える方法。 AIへの指示の目的、背景、制約、出力形式、例を適切に組み立て、改善する活動です。

例： 「ログイン画面を作って」よりも「SPEC.mdのREQ-012を実装し、エラーメッセージとキーボード操作を確認して」のほうが、作業範囲と確認基準を明確にできます。

Harness Engineering​

開発環境とフィードバックの設計。 AIがコードを読んで修正する周辺環境を整備・改善することです。参照文書、ツール、アクセス権限、リポジトリ構造、自動チェック、結果のフィードバックを含みます。

例： プロジェクト規則を文書化し、作業状況を記録して、ビルド・Lint・テストを実行させ、失敗結果を使って修正させます。

Harness Framework​

この教材で用いる名称。 複数のプロジェクトで繰り返し使えるように整理した、ハーネスのファイル構成と作業規則のセットを意味します。業界で合意された単一の標準名称や特定の公式製品名ではありません。

例： AGENTS.md、CLAUDE.md、.github/copilot-instructions.md、docs/、tasks/、verification.jsonを含む開始テンプレート。

比較​

用語主な問い代表的な成果物
Prompt Engineering今回の作業をAIにどう明確に伝えるか指示、例、出力基準
Harness Engineeringどの環境で作業し、どう検証するか文書構造、ツール、権限、検証フロー
Harness Frameworkその環境を次のプロジェクトにも使うには再利用可能なテンプレート、共通ルール

ハーネスがあってもプロンプトは必要です。共通規則は文書に、今回の目標と例外は依頼文に具体的に書きます。

同じ業務での適用例​

1. プロンプト：「REQ-012ログイン画面を実装して」
2. ハーネス：AIがSPEC・DESIGN_SYSTEM・CURRENTを参照
3. 検証：設定済みのテストとビルドを実行し、不具合を修正
4. テンプレート：次のプロジェクトにも文書・検証構造を再利用
