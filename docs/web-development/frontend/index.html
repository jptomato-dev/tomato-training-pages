프론트엔드

이 문서는 웹 애플리케이션의 화면 설계와 구현을 학습하는 개발자와 PM을 대상으로 합니다. HTML/CSS와 SPA의 기본 개념을 알고 있으면 좋습니다.

화면 디자인 (UI/UX)​

UI는 사용자가 접하는 화면과 조작 요소, UX는 업무를 수행하면서 경험하는 전체 과정입니다. 기업용 웹 시스템에서는 미관뿐 아니라 검색 효율, 입력 오류 방지, 접근성, 권한별 표시, 대량 데이터 처리 및 일관성이 중요합니다.

산출물목적
와이어프레임항목과 버튼의 배치 및 정보 구조
목업색상, 글꼴, 간격을 포함한 시각적 설계
프로토타입화면 전이와 조작을 검토하는 모형
디자인 시스템토큰, 컴포넌트, 사용 규칙의 공통 체계
구현 코드실제 데이터, 권한, 오류 처리, 테스트를 포함한 제품

AI 앱 생성v0, Lovable, Bolt, Replit, Google AI Studio실행 가능한 시안과 코드 생성. React 등 생성 기술 스택 확인 필요

우선 검토할 AI 및 디자인 도구​

도구강점주의점
Google Stitch자연어로 복수의 디자인 시안을 탐색하고 코드나 디자인 산출물 활용출력 형식과 Figma 연계, DESIGN.md 지원 범위는 사용 환경에서 확인
Figma Design정밀 화면 설계, 변수, 재사용 컴포넌트, 공동 리뷰학습 비용과 편집 권한·요금 확인
Figma Make동작하는 AI 프로토타입으로 화면 검토생성 코드가 제품의 기술 스택이나 보안 요구를 만족하는지 별도 검증
v0관리자 화면과 데이터 중심의 웹 프로토타입React/Next.js 중심 산출물을 Angular에 그대로 적용하지 않음
Visily / Uizard스크린샷·스케치 등을 이용한 초기 화면 구상생성 결과의 정밀 편집 및 내보내기 제약 확인
Penpot오픈소스 및 자체 호스팅 선택지운영 부담과 AI 연계 방식 확인
Lovable / Bolt / Replit실행 가능한 앱의 빠른 실험데이터 저장, 인증, 의존성, 배포 비용 확인

범용 AI는 요건과 화면 구조를 먼저 논의할 때 유용합니다. 코딩 에이전트는 기존 코드와 공통 컴포넌트를 사용해 구현하는 단계에 적합합니다. 특정 AI가 항상 더 우수하다는 객관적 순위는 아니며 동일한 요구사항으로 비교 실험하는 것이 좋습니다.

Figma와 AI의 MCP 연계​

MCP(Model Context Protocol)는 AI 도구가 외부 도구와 컨텍스트에 접근하는 표준 인터페이스입니다. Figma MCP는 지원되는 클라이언트에서 디자인의 구조, 변수, 레이아웃 등의 정보를 구현에 활용하게 합니다.

Figma 디자인 → Figma MCP → Codex / Copilot / Claude Code
                            ↓
                    Angular / TypeScript / CSS
                            ↓
                     GitHub PR / 테스트 / 리뷰
  1. Figma MCP 공식 문서에서 현재 클라이언트별 연결 방법과 권한을 확인합니다.
  2. 디자인 링크 또는 노드를 지정하고 기존 UI 라이브러리 및 저장소 규칙을 AI에 전달합니다.
  3. 실제 컴포넌트를 재사용하도록 지시하고, 생성한 코드와 디자인을 비교합니다.
  4. 접근성, 반응형, 상태별 UI 및 테스트를 검토한 뒤 PR로 관리합니다.

MCP가 완벽한 코드 변환이나 모든 클라이언트의 디자인 쓰기 권한을 보장하는 것은 아닙니다. 읽기·쓰기 도구, 인증, 요금 제한은 공식 문서 및 조직 정책에 따라 확인합니다.

Angular UI 컴포넌트와 디자인 시스템​

도구특징
PrimeNG테이블, 필터, 트리, 입력 폼 등 업무 화면에 적합
Angular MaterialMaterial Design 기반의 일관된 UI
NG-ZORROAnt Design 기반 기업용 Angular 컴포넌트
AG Grid복잡한 데이터 그리드. 일부 고급 기능은 유료
Storybook공통 컴포넌트의 상태별 확인, 문서화 및 테스트
Playwright실제 브라우저의 화면 조작과 회귀 테스트

React의 MUI와 Ant Design도 참고할 수 있으나 Angular 프로젝트에는 Angular용 라이브러리를 선택합니다. 여러 UI 라이브러리 혼용보다 하나의 기본 라이브러리와 필요한 특수 컴포넌트를 선택하는 것을 권장합니다.

공통 디자인 규칙은 색상(브랜드/주요 조작/성공/경고/오류), 글꼴과 크기, 간격(예: 4/8/12/16/24/32px), 버튼과 입력 폼, 테이블, 상태 표시, 키보드 조작 및 포커스를 포함합니다. 예를 들어 일본어 업무 시스템에서는 Noto Sans JP를 후보로 검토하고, 오류나 승인 상태는 색상뿐 아니라 문구로도 표시합니다. 이는 교육용 예시이며 특정 프로젝트의 확정 규칙이 아닙니다.

추천 워크플로​

단계산출물 및 도구
1. 화면 요건ChatGPT 등으로 역할, 항목, 동작, 수용 기준을 정리하고 Issue 등록
2. 공통 디자인Figma 변수·컴포넌트, UI 라이브러리, DESIGN.md
3. AI 시안Stitch 등으로 여러 대안 비교
4. 상세 설계Figma Design / Make로 레이아웃과 전이 검토
5. 업무 리뷰담당자가 대표 시나리오를 직접 확인
6. 구현VS Code + Codex/Copilot 등, 필요 시 Figma MCP
7. 검증Storybook, Playwright, 접근성 및 반응형 검사
8. 변경 관리GitHub PR, CI, 사람의 리뷰 후 병합

소규모 팀은 Figma 없이 UI 라이브러리와 AI 코딩으로 직접 프로토타입을 만들어도 됩니다. 다만 화면이 많거나 업무 담당자와 합의해야 할 경우 디자인 단계와 구현 단계를 구분하면 재작업을 줄이기 쉽습니다.

실습: 가상의 사원 목록 화면​

목표: 업무 화면의 검색과 목록 표시, 권한별 동작을 설계합니다. 아래는 개념 실습이며 실제 도구에서 실행 검증한 결과는 아닙니다.

  • 입력: 소속 부서, 사원명, 재직 상태
  • 목록: 사원번호, 이름, 부서, 상태, 상세 버튼
  • 화면 상태: 최초 로딩, 검색 결과 없음, API 오류, 권한 없음
  • 조작: 검색, 초기화, 페이지 이동, 상세 표시
  • 수용 기준: 키보드로 조작 가능, 결과 없음과 오류 구분, 권한 없는 변경 요청은 서버에서 거부

AI에 다음과 같이 요청합니다.

일본어 업무용 사원 목록 화면의 디자인 시안을 작성해줘.
좌측 메뉴, 상단 검색 필터, 데이터 테이블을 사용하고
Angular + PrimeNG로 구현할 수 있는 컴포넌트로 구성해줘.
로딩·검색 결과 없음·오류·권한 없음 상태와 키보드 조작을 고려해줘.
실제 개인정보 대신 가상 데이터를 사용하고 디자인 규칙도 정리해줘.

시안을 비교한 뒤 Figma 또는 코드에서 수정하고, Storybook에서 각 상태를 확인하며 Playwright로 검색과 오류 표시를 검증합니다. 화면에서 버튼을 숨기는 것만으로는 인가를 구현할 수 없습니다.

처음에는 DESIGN.md 한 파일로 시작하고 필요할 때 분리합니다. Figma는 시각 설계, GitHub는 업무 규칙·설계 결정·코드의 원본으로 삼을 수 있습니다. 동일 디자인 토큰을 양쪽에서 독립적으로 수정하지 않도록 동기화 책임을 정합니다. 관련 설계 방식은 AI 설계를 참고합니다.

디자인 참고 사이트​

Mobbin은 실제 서비스 사례, Dribbble과 Behance는 디자인 아이디어, Figma Community는 UI 키트, Sakai와 Tabler는 관리자 화면의 참고 자료입니다. 템플릿 라이선스와 사용 기술을 확인합니다.

학습 순서와 추천 조합​

Google Stitch → Figma Design → Figma Make → Figma MCP → PrimeNG → Storybook 순으로 실습하고, v0 및 Penpot은 비교 대상으로 활용하는 것을 권장합니다. 업무 시스템에서는 Stitch + Figma + AI 코딩 + Angular UI 라이브러리 + Storybook/Playwright + GitHub 조합이 한 가지 실용적인 선택입니다.

주의사항과 참고 자료​

경고

외부 AI에 실제 고객·사원 데이터, 비공개 화면, 인증 정보를 업로드하지 마세요. 디자인의 접근성과 실제 서버 권한 검증은 별도로 확인해야 합니다.

제품별 공식 사이트는 위 표에 링크했습니다. 기능과 플랜은 변경될 수 있으며, 이 문서는 2026-11-29 교육용 비교로서 개별 제품의 최신 요금·지원 버전·MCP 쓰기 기능을 모두 재검증한 자료는 아닙니다. 도입 전에 공식 문서를 확인하세요.

  • WCAG 2.2 — 접근성 기준
  • Angular 공식 문서
  • Figma MCP 공식 문서
